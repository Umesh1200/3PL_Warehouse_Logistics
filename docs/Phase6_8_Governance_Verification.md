Restoration is an authenticated SuperAdmin maintenance operation. It restores captured materialized effects rather than recalculating historical policies from current configuration. Each selected row partition receives its latest complete captured effect; cumulative snapshots are never summed. FromBeginning selects all captured partitions; DateRange selects partitions touched by events in the inclusive timestamp window, then restores their latest complete state using the full journal. FromWatermark selects journal events missing processed receipts, including equal-sequence unseen identities. Existing receipts lacking payloads cause rejection before mutation. Unknown kinds, schema versions, invalid hashes, unknown/missing properties and invalid typed values fail preflight. Unknown legacy rows are preserved; this is journal-owned partition restoration, not erasure of unproven historical state.

Journal rows and canonical InventoryMovementEventLogs are never removed by restoration. Movement-only inventory streams lack full receipt/aging evidence and are rejected rather than inventing receipt/movement/demand dates.

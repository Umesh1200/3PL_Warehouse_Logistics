## 1. Executive Summary

A comprehensive, read-only audit of the Nexus3PL repository (`Domain`, `Application`, `Infrastructure`, `WebApi`, `Nexus3PLFrontend`, EF Core migrations, `DbInitializer`, and test suites) reveals a pronounced **implementation asymmetry**:

1. **Strong Core Operational & Billing Domain Foundations:** The repository already contains mature, concurrency-hardened domain entities and infrastructure services for warehouse layout (`Facility`, `WarehouseZone`, `Location`, `DockDoor`, `PackagingMaterial`, `HandlingUnit`), operations policies (`AllocationPolicy`, `PutawayStrategyRule`, `SlottingPolicy`, `InventoryAgingPolicy`, `AbcClassificationPolicy`, `ProductAffinityPolicy`, `MonitoringRule`, `CarrierContractualSlaPolicy`, `StorageBillingPolicy`), and financial ledgers (`RateCard`, `RateCardSchedule`, `RateCardLine`, `RateCardTier`, `CarrierRateAgreement`, `ClientFreightAgreement`, `BillableActivity`, `BillingPeriod`, `Invoice`, `InvoiceSequence`, `CreditNote`, `CustomerPayment`).
2. **Severe API, UI & Wiring Disconnection:** A large portion of these DB-backed masters have **zero WebApi controllers or Admin UI screens**. Most notably, **Module 5 (Financial Master)** has 26 domain entities and 11 fully implemented Infrastructure services, yet **zero REST controllers** and a static frontend placeholder (`App.tsx` `/app/billing`). Similarly, `FacilitiesController` is read-only (`GET` only), `Zones` have no controller, `AllocationPolicies` and `ProductAffinityPolicy` have no endpoints, `CarrierRateAgreement` is disconnected from live shipping rate quotes, and `PrivateObjectStorageService` generates `/api/v1/storage/download` links with no `StorageController`.
3. **Widespread Implicit US / USD / Metric Hardcoding & Missing Legal-Entity Separation:** Despite ISO 4217 validation support in `Iso4217Currencies` (including `"NPR"`), `"USD"`, `"USA"` / `"US"`, `"America/Chicago"`, `"UTC"`, `"KG"`, `"cm"`, and simulated US carriers (`"SIM-FEDEX"`, `"SIM-UPS"`, `"SIM-USPS"`, `"SIM-FREIGHT"`) are hardcoded across Domain defaults, Services (notably `ShippingLabelService` ignoring `Facility` addresses in favor of Columbus, OH), `DbInitializer`, `Schemas/client.json`, and React components (including 24 unscoped `.toLocaleDateString()` / `.toLocaleString()` calls and `Intl.NumberFormat` absence). Additionally, physical `Facility` entities have no link to an issuing `LegalEntity` (seller tax identity/PAN/EIN/billing identity).
4. **Absent Global, Tax/VAT, Transport Master & External Integration Bounded Contexts:** There are **no entities or catalogs** for Countries, Administrative Divisions (Provinces/Districts/Municipalities), Currencies/Dynamic FX, Languages/Locales, Work Calendars/Holidays, Taxes/VAT/PAN, `CountryCompliancePolicy` applicability rules, Shipping Zones/Coverage Areas, Carriers/Couriers, Fleets/Vehicles, Replenishment/Cycle Count/Picking Policies, or External Integration Connectors/Credential Vaults.
5. **Metadata UI Architecture (`ADR-007`) Only 10% Realized:** `SchemasController` and `GetEntitySchemaQueryHandler` serve only a single embedded schema (`client.json`) without tenant overlays, dynamic lookup endpoints, nested collection repeaters, effective-dating controls, or working `date`/`datetime` inputs; `DynamicEntityPage.tsx` still branches explicitly on `'client'`.

## 3. Detailed Existing vs. Missing Repository Inventory

Classification legend used below:
- **A — Implemented & Administrable**: Domain/DB + API + Admin UI (or active user workflow) present.
- **B — DB-Driven, Missing API / UI**: Domain entity & EF table/logic exist, but WebApi endpoints and/or UI are absent or incomplete.
- **C — Partially Configurable / Hardcoded Defaults**: Works via static defaults, inline constants, `appsettings`, or limited fields with hardcoded fallbacks.
- **D — Missing Entirely**: No Domain entity, service, endpoint, or UI exists.
- **E — Requires External Provider Integration**: Architectural hook exists (or is needed), requiring third-party API/SDK/statutory portal connectivity.
